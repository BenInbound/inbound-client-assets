A note on language. This report is written in English for internal review, but inbound.no is a Norwegian site (<html lang="no">). Schema.org property keys are always English and cannot be translated. Property values must match the language of the page they sit on, so every content value in the JSON-LD below is written in Norwegian, and every block that schema.org permits it on sets "inLanguage": "nb-NO". That property is only valid on CreativeWork and Event types, so it is deliberately absent from the Organization, Service, Person and OfferCatalog blocks – those carry knowsLanguage instead, or rely on the page's own lang attribute. A language mismatch between schema and page content signals to AI engines that the markup may not represent the page, which hurts visibility rather than helping it.Om språk. Denne rapporten er skrevet på norsk, og inbound.no er en norsk nettside (<html lang="no">). Property-navnene i schema.org er alltid på engelsk og kan ikke oversettes. Verdiene må matche språket på siden de ligger på, så alt innhold i JSON-LD-en under er skrevet på norsk, og hver blokk som schema.org tillater det på setter "inLanguage": "nb-NO". Testing, before and afterTesting, før og etter

All schema should pass two validators. They catch different things: Google checks whether the markup qualifies for rich results, schema.org checks whether it is valid at all.Alt schema bør gjennom to validatorer. De fanger forskjellige ting: Google sjekker om markeringen kvalifiserer til rike resultater, schema.org sjekker om den i det hele tatt er gyldig.
